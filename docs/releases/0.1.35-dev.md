# AirLink ISP OS 0.1.35-dev

This update adds a local system terminal and corrects monitoring readiness during slow device polling.

- On the AirLink PC's own screen, sign in as owner and choose **PC settings → System → Open Terminal**. Confirm root access. Type `exit` to return to the locked sign-in screen. Sessions and their child processes close after 15 minutes or when the console service stops. No browser terminal is added.
- Terminal access is checked against the live owner session. Active updates and pending restarts block it; failed or interrupted update states remain accessible for recovery. Opening and closing are logged, and shell history is not saved.
- Monitoring now reports scheduler health during device polling instead of waiting for the entire batch. Database and Redis failures still prevent successful heartbeat renewal. Slow devices no longer hold up the monitor's first health signal. Device availability, failure thresholds and confirmed outage history retain their existing behavior.

Install through **Software Updates → Check again → Update now**. This signed application update includes no database migrations.

**Already failed updates:** publishing or downloading this release does not clear an existing failed-installation lock. Review the installed package, migration state and update journal locally before retrying. The new Terminal button appears only after this release is installed; older systems may need their existing administrator access or installer-media Recovery Mode.

This is a development application update, without a new installer ISO or base-OS/driver upgrade. Hardware or service failures unrelated to heartbeat timing still require diagnosis.
