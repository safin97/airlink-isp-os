# AirLink ISP OS 0.1.46-dev

Owners can open a system terminal in Diagnostics and enable PuTTY/SSH access on port 2742 from Settings. SSH uses the linked owner's AirLink login password.

- **Browser terminal:** an owner-only interactive root shell with password confirmation, terminal resizing, keyboard controls and automatic session cleanup. Active terminal sessions hold the maintenance lock to prevent overlapping updates. Opening and closing sessions is audited; terminal contents and passwords are not logged.
- **SSH remote access:** disabled by default, restricted to owner-selected client IP addresses or networks, with Linux username `airlink-admin` on TCP port `2742`. The dashboard shows the server fingerprint. Direct root login and SSH forwarding are disabled; administrative commands use password-protected `sudo`.
- **Account password synchronization:** enabling SSH links it to the configuring owner. Changing that owner's login password updates the SSH password. During synchronization the Linux account is locked; an incomplete synchronization displays a recovery message, and saving SSH settings with the current login password restores access.
- **Existing appliances:** Settings offers an OpenSSH component installer when needed. Installation uses the PC's configured package repositories and retains the existing maintenance and recovery checks. The component is not enabled automatically.

See `docs/SYSTEM-TERMINAL.md` and `docs/SSH.md` for usage and access controls. No database migration is added by this release.

This is a signed development application update for Software Updates and the `.airlink-update` offline bundle. It does not replace the installer ISO, automatically install on existing servers, or clear a failed PC update. A PC reporting “local recovery review” still requires diagnosis and repair before its blocked update can proceed. Remote access also requires the network and firewall to permit the selected connection; publishing this release does not configure a production router.
