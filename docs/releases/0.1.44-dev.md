# AirLink ISP OS 0.1.44-dev

Owners can delegate administrative features to managers through explicit View, Edit and Delete permissions. The dashboard and API enforce the same grants, including permission changes during existing sessions and queued Bluetooth operations. Delegated managers cannot grant stronger permissions or take over accounts outside their access and inventory scope. New administrative grants default to off.

- **Shared payment setup:** authorized staff use owner-selected FIB and FastPay merchant accounts while retaining their own SAS4 permissions. FIB recharge has a separate role grant. Existing orders preserve their merchant credential snapshot and payment verification safeguards. The additive `a53cd2694e70` migration selects an existing merchant only when exactly one active owner configured that provider; ambiguous configurations require an explicit selection in Payment setup.
- **TTLock Bluetooth permissions:** the native app explains and requests the required Bluetooth permissions, refreshes permission state on resume, and respects delegated control and deletion grants. Hardware operations retain their existing confirmation and recovery checks.
- **GPU diagnostics and updates:** clearer GPU model identification, including the laptop GTX 1660 Ti, and a reviewed PC Updates plan for missing supported NVIDIA drivers. Existing driver installations are preserved. Driver installation remains an explicit PC Updates action and may require a restart and local Secure Boot key enrollment.

See `docs/ACCESS-ROLES.md`, `docs/PAYMENTS.md`, `docs/TTLOCK.md` and `docs/GPU.md` for configuration and limits.

This is a signed development application update, available through Software Updates or the `.airlink-update` offline bundle. It does not replace the installer ISO or base OS. Publishing makes it available; existing servers update only after installation. Real bank transactions, Bluetooth hardware and GPU installation require provider/hardware validation; release tests do not perform those operations.
