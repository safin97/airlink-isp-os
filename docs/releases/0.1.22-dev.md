# AirLink ISP OS 0.1.22-dev

- Update health checks wait for the API, required services and both worker heartbeats together. A worker still completing its first iteration no longer fails the check immediately after API startup.
- Failed checks name the unavailable service, worker heartbeat or API/database/Redis endpoint. The updater saves these details for PC settings and Diagnostics and retains command output in the update journal.
- Periodic health checks have an explicit service timeout that allows the bounded startup retries to finish.

Existing failed installations remain locked until local recovery review. This release does not clear failure markers or claim to repair an already failed appliance remotely. The observed 0.1.20 health-check failure still requires that appliance's journal to establish its specific cause.

This is a signed development application update. It preserves the existing database migrations and does not upgrade the kernel/base OS.
