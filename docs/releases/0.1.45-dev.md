# AirLink ISP OS 0.1.45-dev

Device monitoring preserves last reported readings through outages, records downtime with start and recovery times, and keeps wireless clients in a stable order as they disconnect and reconnect. Payment setup can restrict each merchant account to selected AirLink managers.

- **Outage history and retained readings:** tower devices show downtime in minutes and clock times, highlight offline rows in red, and retain SSID, client count, Ethernet speed and reported uptime. Uptime freezes during an outage; collection timestamps distinguish retained readings from new measurements.
- **Wireless client history:** known clients keep their row position across refreshes and service restarts. Complete registration checks establish Up/Down status; partial or failed checks show Unknown. Last-seen times and readings remain available. MikroTik API polling includes all supported radio families.
- **Ethernet ports:** click a device's Ethernet reading to see reported Ethernet/SFP ports, including disconnected and disabled ports, link speed and RX/TX traffic. Standard SNMP interface data is available across vendors and SNMP versions. Ruijie/Reyee displays actual port names and recognizes an explicit RG-EST450G model. Model-specific Ruijie wireless collection still requires device validation; unreported SSID, signal and client readings remain unavailable.
- **Payment manager access:** configure FIB and FastPay independently for all authorized users or selected managers. An empty selection allows owners only. The API enforces assignments before new payments; existing payments retain their merchant snapshot and verification flow. Existing configurations keep their current access until changed.
- **Twilio WhatsApp:** replaces the direct Meta integration with approved Twilio Content templates, explicit customer enrollment and durable delivery tracking. Upgrades retain Meta history and encrypted settings, cancel old pending notifications and disable old enrollments. Twilio credentials, templates and customer permission must be configured separately; Meta credentials and consent are not reused.

The update includes migrations `b64de3705f81`, `c75ef4816092` and `d86fa5927103`. See `docs/MONITORING.md`, `docs/PAYMENTS.md` and `docs/TWILIO-WHATSAPP.md` for configuration and limits.

This is a signed development application update for Software Updates and the `.airlink-update` offline bundle. It does not replace the installer ISO or base OS and does not automatically install on existing servers. Provider responses are simulated in automated tests; real bank payments, Twilio delivery and physical device behavior require their corresponding account or hardware validation.
