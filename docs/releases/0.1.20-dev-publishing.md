## 1. Select the reviewed source and confirm the publisher

After the reviewed version-20 source is merged to `main`, run these commands in one Bash session from the repository root. Start with a clean checkout; the ignored signing directory and build outputs may remain.

```bash
set -euo pipefail
test -z "$(git status --porcelain)"
git fetch origin main --tags
git switch --detach origin/main
RELEASE_COMMIT=$(git rev-parse HEAD)
VERSION=0.1.20-dev
TAG="v$VERSION"
SEQUENCE=21
PACKAGE="dist/packages/airlink-isp-os_${VERSION}_amd64.deb"
STAGED="dist/github-release-${VERSION}"
if git show-ref --verify --quiet "refs/tags/$TAG"; then
  echo "Release tag already exists; stop and inspect it." >&2
  exit 1
fi
mkdir -p dist/publisher-checks
curl --fail --location --proto '=https' --proto-redir '=https' \
  https://github.com/safin97/airlink-isp-os/releases/latest/download/stable.json \
  -o dist/publisher-checks/previous-stable.json
PYTHONPATH=backend:os/updates .venv/bin/python - <<'PY'
import hashlib, json
from pathlib import Path
from cryptography.hazmat.primitives import serialization
from airlink import __version__
from update import verify_manifest
assert __version__ == '0.1.20-dev'
assert 'version: 0.1.20+21' in Path('frontend/pubspec.yaml').read_text().splitlines()
trusted = Path('deployment/update-source/update-public-key.bin').read_bytes()
assert hashlib.sha256(trusted).hexdigest() == 'b4ae47eb2992e80384df54d23e0b7300bc85aac7813ae21ca44b5fc2a31fda9e'
key = serialization.load_pem_private_key(Path('.release-secrets/publisher-private.pem').read_bytes(), password=None)
assert key.public_key().public_bytes(serialization.Encoding.Raw, serialization.PublicFormat.Raw) == trusted
previous = json.loads(Path('dist/publisher-checks/previous-stable.json').read_text())
verify_manifest(previous, trusted)
assert (previous['manifest']['version'], previous['manifest']['sequence']) == ('0.1.19-dev', 20)
print('Source versions, original publisher key, and previous signed feed verified.')
PY
```

## 2. Build the application package

The existing Docker recipe creates the Debian 13 / Python 3.13 runtime at `/opt/airlink`. The package builder copies that runtime and the rebuilt web assets. Use these application-package commands; `os/build/build.sh` additionally builds an installer ISO and is unnecessary here.

```bash
(
  cd frontend
  CI=true flutter pub get
  CI=true flutter build web --release --no-pub --no-web-resources-cdn --dart-define=API_BASE=
)
```

Check `git diff` before proceeding. Flutter 3.47 may add platform exclusions to `frontend/analysis_options.yaml`; review and remove only those generated additions so the packaged source still matches the reviewed commit. Do not discard unrelated edits. Then continue:

```bash
git diff --exit-code
docker build --platform linux/amd64 -f os/build/Dockerfile \
  -t "airlink-isp-os:$VERSION" .
mkdir -p dist/packages
docker run --rm --platform linux/amd64 \
  -v "$PWD/dist/packages:/output" "airlink-isp-os:$VERSION" \
  bash /opt/airlink/os/updates/build-package.sh "$VERSION" /output
docker run --rm --platform linux/amd64 "airlink-isp-os:$VERSION" \
  /opt/airlink/venv/bin/python -c 'import sys; assert sys.version_info[:2] == (3, 13)'
test "$(dpkg-deb -f "$PACKAGE" Package)" = airlink-isp-os
test "$(dpkg-deb -f "$PACKAGE" Version)" = "$VERSION"
test "$(dpkg-deb -f "$PACKAGE" Architecture)" = amd64

dpkg-deb -c "$PACKAGE" > dist/publisher-checks/package-files.txt
sha256sum "$PACKAGE"
```

Review the dependency output and file list for the Python 3.13 runtime, `/opt/airlink/frontend/build/web`, and expected service files. The application package does not update the kernel or base OS. Preserve the built package and its digest; sign and publish these exact bytes.

## 3. Stage signed assets and rehearse installation

Choose a future expiry appropriate to the publication date. The example below is suitable for the planned November 2026 publication; update it if publication is delayed. The staging directory must not already exist. Run the existing helper unchanged:

```bash
EXPIRES=2027-05-07T00:00:00Z
.venv/bin/python os/updates/github_release.py prepare \
  --repo safin97/airlink-isp-os \
  --key .release-secrets/publisher-private.pem \
  --package "$PACKAGE" --version "$VERSION" --sequence "$SEQUENCE" \
  --expires "$EXPIRES" --notes "docs/releases/$VERSION.md" --output "$STAGED"
(cd "$STAGED" && sha256sum --check SHA256SUMS)
PYTHONPATH=os .venv/bin/python - <<'PY'
import hashlib, json
from pathlib import Path
from updates.update import verify_manifest
staged = Path('dist/github-release-0.1.20-dev')
trusted = Path('deployment/update-source/update-public-key.bin').read_bytes()
meta = verify_manifest(json.loads((staged / 'stable.json').read_text()), trusted, current_sequence=20)
assert (meta['version'], meta['sequence']) == ('0.1.20-dev', 21)
assert meta['url'] == 'https://github.com/safin97/airlink-isp-os/releases/download/v0.1.20-dev/airlink-isp-os_0.1.20-dev_amd64.deb'
package = (staged / 'airlink-isp-os_0.1.20-dev_amd64.deb').read_bytes()
assert len(package) == meta['size'] and hashlib.sha256(package).hexdigest() == meta['sha256']
print('Candidate signature, deployed trust, sequence, package URL, size, and digest verified.')
PY
```

## 4. Tag and publish the verified assets

Write the actual package inspection and VM rehearsal results in `dist/publisher-checks/RELEASE-VERIFICATION.md`. Confirm the source remains at the recorded reviewed commit. Include the source and public configuration assets used by earlier updates. Upload the complete bundle to a draft first; publish it as Latest only after all assets are present. Retain the development designation in its version and release notes.

```bash
test "$(git rev-parse HEAD)" = "$RELEASE_COMMIT"
test -z "$(git status --porcelain)"
test -s dist/publisher-checks/RELEASE-VERIFICATION.md
cp dist/publisher-checks/RELEASE-VERIFICATION.md "$STAGED/"
git rev-parse HEAD > "$STAGED/SOURCE-COMMIT.txt"
git archive --format=tar.gz --prefix="airlink-isp-os-$VERSION/" "$RELEASE_COMMIT" \
  > "$STAGED/airlink-isp-os-$VERSION-source.tar.gz"
cp deployment/update-source/update-public-key.bin deployment/update-source/update-source.json "$STAGED/"
(
  cd "$STAGED"
  sha256sum "airlink-isp-os_${VERSION}_amd64.deb" stable.json release-notes.md \
    RELEASE-VERIFICATION.md SOURCE-COMMIT.txt "airlink-isp-os-$VERSION-source.tar.gz" \
    update-public-key.bin update-source.json > SHA256SUMS
  sha256sum --check SHA256SUMS
)
git tag -a "$TAG" "$RELEASE_COMMIT" -m "AirLink ISP OS $VERSION"
git push origin "refs/tags/$TAG"
gh release create "$TAG" \
  "$STAGED/airlink-isp-os_${VERSION}_amd64.deb" \
  "$STAGED/stable.json" "$STAGED/SHA256SUMS" \
  "$STAGED/release-notes.md" "$STAGED/RELEASE-VERIFICATION.md" \
  "$STAGED/SOURCE-COMMIT.txt" "$STAGED/airlink-isp-os-$VERSION-source.tar.gz" \
  "$STAGED/update-public-key.bin" "$STAGED/update-source.json" \
  --repo safin97/airlink-isp-os --verify-tag --draft \
  --title "AirLink ISP OS $VERSION — Development" --notes-file "$STAGED/release-notes.md"
gh release view "$TAG" --repo safin97/airlink-isp-os --json isDraft,assets
```

Verify that the draft contains all nine listed assets with the expected file sizes, then publish:

```bash
gh release edit "$TAG" --repo safin97/airlink-isp-os --draft=false --latest
```

If any publishing step fails, inspect the remote tag and release before retrying. Never reuse the version/tag for a different package.
