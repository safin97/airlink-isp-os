# AirLink ISP OS 0.1.26-dev

- Online users and registration-client PPPoE usernames refresh on the server before opening a page or signing in. Both pages share an account-scoped snapshot of active SAS4 sessions, with background refreshes targeting about 30 seconds. Opening these pages reads collected data instead of starting the collection.
- Customer device signal, SSID and Ethernet readings continue collecting while the browser is closed, in rotating batches with bounded concurrency. Slow device probes do not block online-session refreshes. Cached readings remain isolated by account, saved credentials and customer session.
- The interface identifies initial collection and delayed or unavailable session refreshes. A restart or a newly configured connection needs an initial collection. Incomplete session lists are not used for PPPoE username matching.
- Towers API, Device login, Account profile, Customer device access and Payment setup are owner-only. The server also blocks direct non-owner requests to their configuration APIs. Other accounts retain Change password and their existing authorized customer recharge operations.
- Online users hides the Device access and Connection columns.
- Completed device downtime is recorded when the device comes back online and is available in Monitoring history. The new database migration preserves current inventory and settings; it does not invent past outages. Existing uptime/downtime display behavior is retained.

- Fixes a PostgreSQL error when saving multiple manager permissions: audit entries now retain the full permission details without the old 120-character limit. Existing audit records are preserved.

This cumulative application update includes the earlier AirLink changes. The existing update signing key and update-source configuration are unchanged. Install through Software Updates on a healthy installation; this release does not bypass a failed-installation recovery lock.
