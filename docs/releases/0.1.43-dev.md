# AirLink ISP OS 0.1.43-dev

TTLock now has a responsive light/dark dashboard with device summaries, search and connection filters, grid/list views, battery indicators and device-management tabs. Existing lock names and IDs are preserved. Physical state remains unknown until checked; gateway linkage alone never reports a lock as online. Sensitive commands require confirmation and duplicate requests are guarded.

- **TTLock account and access management:** owner-only account connection, encrypted application/token storage, existing cloud lock listing/naming/control, and separate passcode, RFID-card and fingerprint workflows. Unsupported eKey and gateway-administration APIs remain visibly disabled. Access history displays actual Bluetooth records with unknown fields labeled honestly.
- **Nearby Bluetooth:** Android/iPhone source and native TTLock SDK integration support device communication, pairing and supported access changes. Durable operation records and cloud-sync recovery avoid blindly repeating physical actions. Browser controls can use a nearby native AirLink app through an owner/account-bound foreground phone bridge, with approval on the phone. Direct TTLock Bluetooth in Chrome is not claimed. Native builds require the updated HTTPS backend; iPhone installation requires Apple signing. Physical lock, gateway and phone behavior still needs owner hardware testing.
- **Client portal:** phone-number sign-in, connection diagnostics, improved support contacts, larger branding, light/dark appearance, Kurdish Badini text and slide-to-pay package cards. Shared phone-password access remains an explicit server configuration and is disabled by default; ordinary phone login uses the customer's SAS4 password. Existing subscriber-network matching, separate customer sessions and payment-confirmed package changes are retained.
- **Upgrade compatibility:** includes the client auto-login diagnostics and range controls from the earlier draft release. Four additive TTLock migrations end at `f42bc1583d69`, preserving existing accounts, inventory, encrypted credentials and customer settings.

This is a signed development application update, available through Software Updates or the `.airlink-update` offline bundle. It does not replace the installer ISO or base OS. Publishing makes the update available; an installed server is updated only after installation. No real locks, gateways or customer payments are changed during release validation. See `docs/TTLOCK.md` for supported features and setup.
