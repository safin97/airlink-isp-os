# AirLink ISP OS 0.1.24-dev

This full application update includes all earlier application changes plus:

- **Towers API** in the sidebar: save encrypted device login profiles, share them with selected managers, and select a profile through **Towers → devices → Login device**. The API overview uses the authorized inventory IP and supported RouterOS REST or airOS web access. Saved passwords are never returned. Existing Device login profiles remain reusable.
- **MikroTik switch Ethernet ports**: a dedicated SNMPv2c/public preset and a ports view with connected, disconnected, disabled and unknown states, reported link speeds, and receive/transmit rates. Stale or missing measurements are not displayed as current traffic.
- **Registration clients** shows **PPPoE username** instead of Interface. Names require a unique exact MAC match in active MikroTik PPPoE sessions or the viewing account's SAS4 online sessions. SAS4 matching respects ISP Card access, runs in the background, and never guesses from radio interface names. Missing or ambiguous matches show Unavailable.
- **Mimosa Add/Edit Device** explicitly displays SNMPv2c and community public for the preset, selects it when Mimosa has no assigned profile, and preserves existing saved profiles.
- The local development preview no longer substitutes demo responses for device login or recreates a demo login profile. Restarting it preserves existing saved settings.

Existing accounts, inventory, profiles and encrypted credentials are retained. Remote devices must expose supported services and accept the selected credentials. Switch ports are based on the bounded IF-MIB data reported by the device; rates require two valid samples. If the wireless MAC differs from the PPPoE MAC, a username cannot be matched automatically.

Install through **Software Updates → Check again → Update now**. Signed update sequence: **25**. This is a complete application package, not an installer ISO or an operating-system/kernel upgrade. Physical device compatibility still depends on firmware and configuration; automated checks use controlled fixtures.

The startup health-check improvements from 0.1.22 remain included. An appliance already locked after a failed installation still requires local recovery review; this update does not bypass that lock.
