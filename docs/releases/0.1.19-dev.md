# AirLink ISP OS 0.1.19-dev

- Online Users → Open device accepts temporary device credentials, saved login profiles, or the assigned SAS4 manager login. Temporary passwords stay in request bodies and are not saved.
- Automatic connection detects MikroTik and Ubiquiti device types using SNMP v1, then v2, with the public read community by default. Customer detection accepts either vendor on either version; tower discovery filters remain unchanged. If SNMP is unavailable, device API detection is attempted.
- Compatible web, RouterOS API-SSL/API, and Ubiquiti SSH connections are tried sequentially. The panel displays the detected type, SNMP version and connection attempts. Custom web ports are not reused for SSH/native API.
- RouterOS 6/7 native API and RouterOS REST expose Ethernet, wireless, PPPoE, registered clients and supported system/network details. Ubiquiti airOS M5/AC supports web readings and airOS 6/8 SSH readings and SSID editing. Unknown SSH keys require fingerprint verification before credentials are sent.
- SSID changes require ISP Card edit access and an explicit Save. They use the selected connection, recheck the live SAS4 session and current settings, and never automatically retry an uncertain write. Ubiquiti Save SSID and restart radio commits the preserved configuration and restarts the radio. Other settings remain in the native device interface.
- The tower device table hides the Device name and API status columns. IP addresses, operational status, SNMP status and telemetry remain visible.

Existing accounts, inventory and stored credentials are preserved. No new database migration is required. Device services must be enabled and reachable; the application cannot bypass device login permissions. Physical device firmware interoperability remains unverified; protocol and UI behavior have automated coverage. This is a signed development application update, not an installer ISO or base-OS upgrade. Use Software Updates → Check again → Update now.
