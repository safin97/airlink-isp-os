# AirLink ISP OS 0.1.48-dev

Ethernet fallback counts now distinguish used ports from unused ports. A port becomes Down only after it has been observed running. After moving a cable to another port or switch, authorized tower editors can open Ethernet details and mark the old outage resolved. The resolution remains saved until that port runs again and later goes down.

- **Device readings:** when no wireless SSID is available, the device table shows the saved device name. Retained SSIDs still take priority during an outage.
- **MikroTik CCR:** a dedicated vendor choice uses the existing MikroTik monitoring and login paths. With tower REST API monitoring configured, Registration clients shows the active PPP session count.
- **Ethernet fallback:** when registration-client or PPP counts are unavailable, the column shows Ethernet Running and Down counts. Unused and resolved ports are excluded from Down; unavailable observations remain Unknown or explicitly last-known. Ethernet details refresh as polling detects cable moves.
- **ISP Card:** online-user Ethernet readings use ether1 for MikroTik and eth0 for Ubiquiti. Other ports are not substituted when the required port is unavailable.
- **Online users:** choose 10, 25, 50 or 100 users per page. Changing the page size returns to page 1 while preserving the submitted search; refresh and pagination retain the selection while the page is open.

Ethernet usage and resolution history use the existing telemetry snapshot storage; no new database migration is required. Existing permissions and per-device Ethernet speed selections are preserved.

This signed development application update is available through Software Updates and the `.airlink-update` offline bundle. Physical radio and PPP readings depend on the device's supported telemetry and configured access. The application update does not install GPU drivers, repair PC package recovery failures, replace the installer ISO, or automatically install on existing servers.
