# Telegram notifications

For ISP card activation and three-day expiry messages sent privately to customers, see [Customer Telegram notifications](CUSTOMER-TELEGRAM.md). Customer linking uses a dedicated bot under **ISP card → customer details → Customer Telegram** and is separate from the device-alert settings below.

The owner configures Telegram under **Managers → Edit account → Telegram notifications**, or immediately after saving a new account. Each account has its own encrypted bot token, destination, enable switch and delivery status. Notifications are restricted to devices visible to that account, and permissions are checked again before delivery. Create a bot through Telegram's verified @BotFather, start a conversation with the bot (or add it to a group), and enter the bot token and destination chat ID. A public channel can use @channelname; the bot needs permission to post there. For a numeric chat ID, Telegram's getUpdates method returns message.chat.id after a message is sent to the bot; keep requests containing the bot token private. Do not share the token in screenshots or support messages.

Save the settings and use **Save and send test** to verify delivery. Enable **Send device down and recovery notifications** for automatic alerts. Tokens are encrypted at rest and are never returned by the settings API. Only the owner can manage the selected account’s connection, templates and test messages. Managers retain separate notification destinations and authorized device scopes.

The alert service sends a notification when an enabled inventory device crosses its configured availability failure threshold, and another when an active down incident resolves with a fresh online reading. Existing incidents are not replayed when notifications are enabled. Unknown/stale telemetry is not described as recovered. The NOC page does not need to remain open. Internet access to api.telegram.org is required.

Notifications use a persistent queue, with up to five delivery attempts and increasing delays. After five failures, inspect the delivery error in Settings and use the test button after correcting the connection. Saving settings discards that account’s pending notifications so old events are not delivered to a different destination. Telegram does not offer an idempotency key for sendMessage; an ambiguous network failure or crash after delivery may produce a duplicate on retry. Successful queue records are retained for 30 days.

Installed systems use airlink-alerts.service. Local **live** mode also evaluates alerts and dispatches enabled Telegram notifications. Demo mode does not automatically dispatch alerts. No bot is connected or message sent simply by installing this feature.

API reference: https://core.telegram.org/bots/api#sendmessage

## Custom messages

Open **Managers → Edit account → Telegram notifications → Next: Edit messages** to edit your own down/timeout and recovery messages. Use `{status}`, `{device_name}`, `{ip_address}`, `{tower_name}`, and `{time}` (UTC) placeholders. Each message allows up to 1,000 characters and has a sample preview. Save messages to apply; Restore defaults changes the editor until saved. Changes apply to newly queued alerts; already queued messages retain their original text. Templates can be saved before connecting a bot.

Choose **Notification language** directly on **Managers → Add/Edit account → Telegram notifications** to use English, Kurdish Badini, or Arabic for each account. **Save** stores the choice; **Save and send test** stores it before sending the test in that language. Continuing to **Next: Edit messages** also saves the selected language. Default messages include the tower name. Switching language updates unmodified default templates and the status preview; custom wording is preserved. Use **Restore defaults** in the message editor to replace custom wording with the selected language's templates, then **Save messages**. The saved language controls alert statuses and connection test messages, independently of the dashboard language. Existing accounts start in English. Arabic and Kurdish editors and previews use right-to-left text; device and tower names, IP addresses, and UTC timestamps retain their original values.
