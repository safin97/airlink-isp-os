# Deye Solar

Open **Deye Solar** and connect using your Deye Cloud app account (email, username, or mobile number with country code). Select the same region as the Deye app: Europe/EMEA/Asia-Pacific, Americas, or India. Deye OpenAPI also requires an **App ID and App Secret** from [Deye's developer portal](https://developer.deyecloud.com/) with station monitoring permission. A normal app login alone does not supply these developer credentials. An optional company ID selects a business organization; otherwise the personal account is used.

Select a station to view solar production, battery state of charge and power, load consumption, grid power, and separate charging/discharging and import/export readings when supplied by Deye. The dashboard reads station-level totals. It does not configure or control the inverter. Missing, malformed and unsupported measurements display as unavailable, while actual zero readings remain zero. Battery/grid signed values are displayed unchanged; directional labels use the separate charge, discharge, purchase and export fields rather than guessing the sign convention.

The main **Dashboard** includes a compact Deye Solar overview for accounts with both Dashboard and Deye Solar access. Small solar, battery, grid and load nodes connect to a central inverter with bridge lines, with their live power readings and battery charge bar. The dashboard card shows only these five components; station selection, cloud status, refresh controls and grid history are in the Deye Solar section. Hover or long-press the dashboard diagram for the latest cloud timestamp or a connection error. Battery power and charging/discharging/idle status are shown, with grid import/export power. Arrows use positive solar/load power and unambiguous charge/discharge or import/export fields from recent cloud readings; missing, conflicting or stale direction data has no arrow. A short flow animation plays when a new cloud observation arrives, respecting reduced-motion settings. It does not imply second-by-second telemetry. Open **Deye Solar** from the navigation menu for the detailed view. Both layouts adapt to phones and support light/dark themes. An unconnected account sees a setup prompt without fabricated readings; connection setup remains in the Deye Solar section. Revoking Deye Solar access also removes the dashboard overview and stops its refresh timer.

To choose the station shown on the dashboard, open **Deye Solar**, choose a **Power station** (use the page arrows if needed), and select **Show this station on dashboard**. The choice is saved per AirLink account and survives reloads and server restarts. Browsing another station does not change the saved dashboard choice. **Use first station automatically** clears the preference. Changing the saved choice requires Deye Solar edit permission. The dashboard picks up preference changes through the live stream or a quiet fallback update if the live connection drops. If a selected station becomes unavailable, it shows an error instead of silently switching to another station. Changing the Deye account, region or application clears the preference; reconnecting the same account preserves it.

AirLink monitors each active, authorized account’s saved dashboard station (or the first station automatically) in the background, targeting a cloud check every 5 seconds. The API service must be running; a slow cloud request or several busy accounts can delay a poll. Authenticated live connections receive updated cached readings within the next two-second live frame, without making extra cloud calls. Healthy live views do not periodically reload over HTTP. If the stream disconnects or stops delivering heartbeats for 10 seconds, a quiet five-second fallback updates the existing diagram without clearing readings or showing a loading bar. The stream reconnects automatically. The detailed view uses the same quiet polling for stations other than the background-monitored dashboard station. Other stations are polled only while viewed. Reading responses are cached per AirLink account and station for five seconds, with temporary failures cached for 30 seconds to avoid rapid retry loops (up to eight stations, retaining the dashboard selection); station lists remain cached for three minutes. The cloud observation time is shown, with readings older than 15 minutes marked stale and missing/ambiguous timestamps marked unknown. Refreshing cannot make the inverter upload faster. Station power fields use watts (displayed as kW for larger values); this convention must be checked against the connected station during live commissioning. The OpenAPI station schema does not include explicit unit metadata.

Connections are scoped to each AirLink user. Owners have access; other accounts need the **Deye Solar** section enabled, with edit/delete permissions to connect or disconnect. Existing accounts receive no new delegated access automatically. Credentials (including the SHA-256 password credential required by Deye) and tokens are encrypted server-side, never returned to the browser, and never placed in audit records. Expiring tokens are renewed automatically; rejected accounts can be reconnected. Changing region/account/application requires fresh credentials. Disconnecting removes only that AirLink account's saved connection/cache.

Grid availability is an **estimate from inverter grid-input voltage**, not from grid watts or cloud connection status. It requires Deye **device-monitoring permission**, a complete inventory of 1–10 inverters in the station, and fresh device measurements with supported `GridVoltage` phase keys and V/mV/kV units. Values at least 50 V on every reported grid channel indicate available; all at most 1 V indicate unavailable. Mixed phases, 1–50 V readings, missing units, unsupported models, offline devices and observations older than 15 minutes are unknown. This indicates voltage presence, not acceptable power quality. Check the readings against the inverter during commissioning.

**Observed uptime**, **observed downtime** and **unknown time** are stored per AirLink account and station from the first monitored sample. Only intervals bounded by distinct fresh samples with the same grid state are counted as uptime/downtime; duplicate samples, transitions, failed requests and gaps longer than 90 seconds between polls are not backfilled as known time. Data persists across reloads. The dashboard station continues recording while the AirLink API runs, even when the browser is closed. Other stations require an open view. Server downtime, revoked permissions and cloud gaps remain unknown; this is a cloud-based estimate, not a direct electrical outage recorder. Inactive accounts and accounts without Deye Solar Read permission are not polled. Disconnecting or changing the cloud account clears its history. Device inventory is cached for 30 minutes; device data follows the five-second reading cache. Device-data failure does not discard available station power readings.

The adapter uses fixed HTTPS regional endpoints and only `/v1.0/account/token`, `/v1.0/station/list`, `/v1.0/station/latest`, `/v1.0/station/device`, and `/v1.0/device/latest`. Redirects are refused. It does not use unofficial mobile app keys or expose arbitrary cloud API calls.

To control manager access, open **Access Roles**, edit **Manager** (or the custom access role assigned to that manager), and find **Deye Solar**. Enable **Read** to show the section; leave **Edit** unchecked for read-only monitoring. Enable **Edit** to allow connecting or changing that account's Deye connection. **Delete** separately permits disconnecting. Disabling **Read** hides the section and blocks its API access, including cached readings. Save the role; its permissions apply to all accounts assigned to it. Each account uses its own saved Deye connection.
