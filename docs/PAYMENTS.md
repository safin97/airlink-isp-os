# Owner-managed FIB and FastPay

The owner configures the shared merchant accounts in **My account → Payment setup** (also available in owner Settings → Payment gateways). Saving a provider selects that owner's encrypted merchant credentials for future checkouts throughout AirLink. Ordinary managers never enter bank credentials and cannot read, change or test merchant settings. The owner may explicitly delegate Payment setup View/Edit through Access Roles. They receive only payment-method availability and environment.

Staff recharge offers Manager balance, FIB Bank and FastPay. Each staff account still needs its own SAS4 access and ISP card editing permission. FIB uses unused SAS4 cards visible to that account and requires its existing SAS4 card permissions; saved local PIN inventory requires the separate Card System grant. FastPay uses the account's permitted manager-balance recharge and verified service price. Sharing a bank account does not share SAS4 credentials or expand customer access. The customer portal retains its existing FIB checkout using the portal's configured SAS4 owner.

The owner enables staff FIB checkout in **Access Roles → edit the assigned role → FIB Bank recharge**. Enable View to preview matching cards and Edit to create a payment; ISP Card View/Edit is also required. The new grant is off for existing managers unless explicitly added. Removing the FIB Edit grant blocks new checkouts immediately and sends already-paid orders to review instead of activating service under a revoked permission. Owner and authenticated customer-portal FIB access continue unchanged.

Orders snapshot the merchant credentials and environment when created. Changing bank setup does not redirect existing payments. Staff can see their own orders; the owner whose merchant account receives a payment can view its status and review uncertain FIB creation using the existing confirmation flow. Other staff cannot see that payment. Disabling/deleting the selected configuring account, or revoking a delegated configuring account’s Payment setup Edit grant, makes that provider unavailable for new orders; AirLink never silently switches to another merchant. Payment verification, PIN reservations, sandbox restrictions and once-only activation are preserved.

The schema migration selects an existing provider configuration automatically only when exactly one active owner configured it. Legacy manager settings are not selected. If multiple owners configured the same provider, an owner must save the intended merchant in Payment setup before new checkouts can use it. Historical configurations and payment snapshots are preserved.
